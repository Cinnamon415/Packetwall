# Packetwall — ожидаемое поведение для e2e

Каждый пункт — проверяемое утверждение «сделал X → видно Y». Тесты в `app/src/androidTest` ссылаются на код пункта
(`@Covers("HOME-03")`). Пункт считается покрытым, только если тест проверяет **все** указанные последствия: в интерфейсе,
в трафике (что прошло и что нет), в журнале (строка, статус, причина) и в сохранённом состоянии (после перезапуска процесса).

Общие правила для всех проверок трафика:
- Блокировка доказывается тремя вещами сразу: соединение не прошло; контрольное соединение рядом прошло (сеть жива);
  в журнале есть строка этого соединения со статусом «Заблокировано» и причиной (правило / список / внутренняя).
- Разрешение доказывается ответом сервера (HTTP-статус), а не отсутствием ошибки.
- Трафик идёт от uid оболочки (`Shell`) через VPN; собственный трафик Packetwall в VPN не попадает.
- Ни одна проверка не может пройти, если сеть эмулятора недоступна: перед набором — проверка доступности без VPN.
- Заблокированное имя получает ответ 0.0.0.0 с TTL 10 с, и Android (netd) его кэширует: после снятия блокировки
  проверка берёт новое имя (поддомен) или ждёт 11 с. Для проверок «заблокировано/нет» годится и несуществующий поддомен.
- Время в Compose-тестах виртуальное: задержки внутри экрана (поиск по спискам через 250 мс после ввода) тест
  продвигает часами `mainClock`, а не ожиданием.

## APP — каркас, шторка, навигация

- APP-01 Первый запуск без разрешения VPN: «Включить» показывает системный диалог; «Отмена» → защита выключена, тост «VPN permission was not granted»; «OK» → защита включается.
- APP-02 Шторка: каждый пункт открывает свой экран (Главная, Журнал, Статистика, Анализ файлов, Поиск, Приложения, Глобальные правила, Списки, Наборы и профили, Настройки, О приложении); активный пункт подсвечен; в шапке шторки статус «Вкл/Выкл».
- APP-03 «Назад»: закрывает открытую шторку; на вложенном экране возвращает на предыдущий; на корневом — выходит из приложения.
- APP-04 Поворот экрана и пересоздание activity не теряют текущий экран, вкладку, введённый фильтр.
- APP-05 Чужое приложение не может выключить защиту через exported activity (любые action/extras игнорируются).
- APP-06 Тема (Настройки → Оформление): Светлая/Тёмная/Системная меняют тему сразу и сохраняются после перезапуска.
- APP-07 Совет про постоянную VPN показывается один раз после первого запуска защиты без «постоянная VPN + блокировка»; «Позже» и «Настройки VPN Android» закрывают его навсегда; при включённых постоянной VPN и блокировке не показывается.
- APP-08 Состояние постоянной VPN перечитывается при возврате в приложение (включили/выключили в Android, пока защита работает → текст в Настройках меняется без перезапуска защиты); при выключенной защите — «Состояние видно после включения защиты».
- APP-09 Нет падений и JNI-ошибок в logcat за весь прогон.

## SYS — уведомление, плитка, виджет, перезапуск

- SYS-01 Включение защиты → постоянное уведомление «Packetwall is filtering traffic» с кнопками «Пауза» (если пакеты хранятся) и «Стоп».
- SYS-02 «Стоп» в уведомлении выключает защиту: tun0 исчезает, Главная показывает «Выкл», уведомление пропадает.
- SYS-03 «Пауза» в уведомлении → уведомление «на паузе» с «Продолжить»; Главная — состояние «Пауза»; «Продолжить» возвращает обычный режим.
- SYS-04 Нажатие на уведомление открывает приложение.
- SYS-05 Плитка быстрых настроек: отражает состояние (активна/неактивна, подзаголовок — профиль или «Выкл»); нажатие включает и выключает защиту; без разрешения VPN открывает диалог разрешения.
- SYS-06 Виджет: кнопка питания включает/выключает, имя профиля переключает на следующий профиль, статус открывает приложение; вид обновляется при смене состояния.
- SYS-07 Быстрое выкл/вкл (3 раза подряд) — защита в итоге включена и фильтрует.
- SYS-08 Другой VPN забирает соединение (onRevoke) → защита выключена, интерфейс показывает «Выкл».
- SYS-09 Обновление приложения при включённой постоянной VPN → Android перезапускает защиту, правила действуют.
- SYS-10 Перезагрузка с постоянной VPN + блокировкой → защита поднимается сама, статус в Настройках «включена, соединения без VPN блокируются».

## HOME — главная

- HOME-01 Выкл: карточка «Выкл», строка «VPN · <профиль>», одна кнопка «Включить»; плитки полупрозрачные; графика скорости нет.
- HOME-02 «Включить» → карточка «Вкл», строка «<время> · VPN · <профиль>[ · DoH <хост>]», кнопки «Пауза» и «Выключить»; время растёт каждую секунду.
- HOME-03 В режиме «только файрвол» (не хранить пакеты) кнопки «Пауза» нет — ни на Главной, ни в уведомлении.
- HOME-04 «Пауза» → карточка «Пауза» (цвет предупреждения) с длительностью; кнопки «Продолжить», «Выключить»; правила продолжают блокировать; новые соединения не попадают в журнал; «Продолжить» снимает паузу.
- HOME-05 «Выключить» → «Выкл», tun0 исчезает, трафик идёт мимо (не логируется).
- HOME-06 Плитки: «Соединения» = число соединений за сеанс (и больше 20000: в памяти хранятся последние 20000, счётчик не упирается в предел); «Заблокировано» = число заблокированных; «Получено» = байты; «Активные» = активные соединения. После известного трафика значения совпадают с журналом.
- HOME-07 Нажатие на плитку: «Соединения» → Журнал, фильтр «Все»; «Заблокировано» → Журнал, фильтр «Заблокированные»; «Получено» → Статистика; «Активные» → Журнал с фильтром `active`.
- HOME-08 Значки в шапке: график → Статистика; журнал → Журнал как его оставили (фильтр, чип и вкладка не сбрасываются).
- HOME-09 «Последние блокировки»: до 5 последних заблокированных (новые сверху), у строки хост и «приложение · время»; пусто → «Nothing blocked yet»; кнопки «Разрешить» нет.
- HOME-10 Нажатие на строку блокировки → экран соединения; «‹ ›» на нём ходят по этим пяти.
- HOME-11 Долгое нажатие на строку блокировки → лист быстрого правила (QR-*).
- HOME-12 «Все» у «Последних блокировок» → Журнал с фильтром «Заблокированные».
- HOME-13 «Статистика»: до 5 приложений по трафику, по убыванию, полоса пропорциональна.
- HOME-14 Нажатие на статус (иконка/название) → меню профилей; выбор профиля переключает его (строка статуса, плитка, виджет обновляются), правила нового профиля действуют сразу; «Наборы и профили» → экран наборов.
- HOME-15 Строгий частный DNS у сети → под статусом красная строка «Private DNS is strict…».
- HOME-16 Широкий экран (≥600 dp): статус слева, 4 плитки в ряд; кнопки статуса друг под другом.
- HOME-17 Значок приложения у каждой строки (последние блокировки, Статистика, журнал) — значок её приложения, и после того, как список сдвинулся новыми строками другого приложения.

## LOG — журнал

- LOG-01 Выкл и журнал пуст → «Turn protection on to see connections»; Вкл и пусто → «No connections yet».
- LOG-02 Каждое соединение от Shell (TCP, UDP, DNS, ICMP) появляется строкой: приложение, «протокол, порт», хост (или IP), статус (Активно/Закрыто/Заблокировано — цветом), время, байты. Подзаголовок «показано / всего» верен.
- LOG-03 Новые сверху. Закрытое соединение меняет статус с «Активно» на «Закрыто» без перезахода.
- LOG-04 Чипы «Все / Заблокированные / Разрешённые» фильтруют по статусу; счётчик «показано / всего» меняется.
- LOG-05 Компактный вид (чип с иконкой): строки в одну-две линии, заблокированные — с красной полосой слева; переключается обратно.
- LOG-06 Фильтр-выражение: `host ~ x`, `app == "Shell"`, `port == 443`, `proto == DNS`, `bytes > N`, `blocked`, `allowed`, `active`, `tracker`, `&&`/`and`, `||`/`or`, `!`/`not`, скобки, `!~`, `<=`, `>=`, сравнение без учёта регистра; текст без операторов — поиск по подстроке. Каждый вариант даёт ровно ожидаемые строки.
- LOG-07 Ошибочное выражение: поле подсвечено как ошибка, под ним текст ошибки (незакрытая кавычка, неизвестное поле, нет `)`, нет оператора, обрыв); список не обнуляется молча.
- LOG-08 «?» открывает справку по фильтру; нажатие на пример подставляет его в поле и применяет; все примеры разбираются без ошибки.
- LOG-09 Вкладка DNS: только DNS-запросы; у строки имя и ответ (`→ IP`) или «blocked → answered locally» для заблокированного имени.
- LOG-10 Вкладка HTTP: только соединения с URL (незашифрованный HTTP); строка — хост и путь.
- LOG-11 Нажатие на строку → экран соединения; «‹ ›» ходят по отфильтрованному списку, на краях неактивны.
- LOG-12 Долгое нажатие на строку → лист быстрого правила (QR-*).
- LOG-13 Меню «⋮» → «Export shown as CSV»: системный диалог сохранения; файл содержит заголовок и ровно показанные строки (с учётом фильтра) с верными полями `status`, `blocked`, `rule`, `route`.
- LOG-14 «⋮» → «Export packets of shown connections (pcapng)»: файл читается (capinfos/разбор), содержит пакеты только показанных соединений.
- LOG-15 Кнопка «Наверх»: появляется при прокрутке (если от верха больше полэкрана), прячется через 3 с после остановки и у верха списка; нажатие доводит до самой новой строки.
- LOG-16 Ползунок: появляется при прокрутке, гаснет через 1,5 с; перетаскивание прокручивает список пропорционально; во время перетаскивания пузырь со временем строки в середине экрана и «сегодня»/дата; кнопка «Наверх» в это время скрыта.
- LOG-17 Фильтр, чип статуса, вкладка и компактный вид переживают поворот, уход на другой экран (меню, значок журнала на Главной, «Назад»), закрытие приложения и перезапуск процесса. Сбрасывает их только переход с готовым фильтром (плитки Главной, Статистика, история приложения).
- LOG-18 Пауза: новые соединения в журнал не попадают; после «Продолжить» снова попадают.
- LOG-19 Выключение и включение защиты: при хранении «только текущий сеанс» журнал очищается при новом запуске.
- LOG-20 Журнал на диске (Настройки → хранить N дней): закрытые соединения остаются после перезапуска процесса и защиты (видны сразу в новом сеансе); «только заблокированные» сохраняет на диск только их; «Очистить сохранённый журнал» удаляет.
- LOG-21 Из Главной/Статистики журнал открывается с переданным фильтром и вкладкой «Соединения».
- LOG-22 Список у самого верха следует за новыми соединениями: они появляются на экране, верхняя строка — самая новая. Прокрученный вниз список стоит на месте: новые строки добавляются выше, видимые строки не сдвигаются.

## CONN — экран соединения

- CONN-01 Заголовок — хост (или IP), подзаголовок «#id · приложение · протокол».
- CONN-02 Обзор: Правило (почему разрешено/заблокировано: правило с целью, «для кого» и набором; список «list <имя>»; внутренняя причина: DNS, частный DNS, QUIC, kill switch, UDP прокси), Протокол, Статус, Приложение (uid), Пакет, Источник, Назначение (страна), Хост, Трекер, AS, Маршрут (только если настроен прокси), Трафик, Пакеты, Начало, Последняя активность — значения совпадают с фактическим соединением.
- CONN-03 «Добавить правило» → лист быстрого правила; «Правила приложения» → экран правил этого приложения.
- CONN-04 Значок «Экспорт pcapng» → файл с пакетами только этого соединения.
- CONN-05 Вкладка «Пакеты»: список пакетов (направление, размер, сводка); нажатие → экран пакета (разбор слоёв, hex). Без хранения пакетов — «Packet capture is off»; пакет вытеснен из буфера — «The packet is no longer in the buffer».
- CONN-06 Вкладка «Данные»: полезная нагрузка в режимах Авто/Текст/Hex; без нагрузки — «No payload…».
- CONN-07 Вкладка HTTP: запрос и ответ для HTTP; для TLS — «Encrypted (TLS)…» и разбор Client Hello / сертификата; для QUIC — «QUIC / HTTP/3: encrypted».
- CONN-08 Соединение исчезло из журнала (очистка, новый сеанс) → «The connection is no longer in the list».

## QR — быстрое правило (долгое нажатие на соединение, «Добавить правило»)

- QR-01 Лист показывает иконку и имя приложения, «протокол · хост».
- QR-02 Для разрешённого соединения по умолчанию «Блокировать», «Для приложения» (если uid ≥ 0), цель — базовый домен с поддоменами (если хост — имя), набор — «По умолчанию».
- QR-03 Варианты цели: точный хост; базовый домен «+ поддомены»; IP; подсеть (/24 или /64); «Весь трафик приложения» (только «Для приложения»). Переключение на «Глобально» убирает «Весь трафик» и сбрасывает выбор с него.
- QR-04 Кнопка «Блокировать» создаёт правило с выбранными «кто/цель/набор»; тост «Rule added»; правило видно в списке правил приложения/глобальных; новое соединение к цели блокируется (вместе с DNS-ответом 0.0.0.0 для имени), контрольное — проходит.
- QR-05 Для заблокированного правилом соединения: блок «Заблокировано правилом <цель> · <кто> · <набор>» с кнопкой «Удалить блокирующее правило» → правило удалено, снэкбар «Отменить» возвращает его; после удаления соединение проходит.
- QR-06 Для заблокированного: по умолчанию «Разрешить», набор — набор блокирующего правила (или ближайший пользовательский выше списка), цель — цель блокирующего правила.
- QR-07 Предупреждения при разрешении: набор ниже блокирующего → «The block comes from “X”… would not apply»; глобальное исключение против правила приложения → «…Choose “For this app”»; более широкая цель → предупреждение; если исключение сработает — предупреждения нет. Предупреждение совпадает с фактом: после сохранения соединение действительно проходит (или нет).
- QR-08 Соединение без uid (uid < 0): «Для приложения» недоступно.

## RULE — редактор правила

- RULE-01 «Добавить правило» на глобальных: по умолчанию Блокировать, Домен, «+ поддомены» отмечено, набор — выбранный в чипах или «По умолчанию».
- RULE-02 «Добавить правило» у приложения: по умолчанию «Всё»; глобальное «Блокировать всё» без порта и протокола показывает красное предупреждение (отрезает всё).
- RULE-03 Проверка цели: домен (маски `*`, `**`), IP/CIDR (v4, v6), ASN (`AS13335`), страна (2 буквы). Неверное значение — поле красное, «Сохранить» неактивно. Порт: пусто или 1–65535, иначе ошибка.
- RULE-04 Протокол `* / TCP / UDP / ICMP` и порт уточняют правило: блок TCP/80 на IP не трогает TCP/443 того же IP.
- RULE-05 «Reject» (только для блокировки): TCP — мгновенный отказ (RST, < 1,5 с), а не таймаут; UDP — ICMP unreachable; DNS — NXDOMAIN. Без «Reject» — drop (таймаут).
- RULE-06 Маршрут (только для разрешения): По умолчанию / Напрямую / Через прокси — при включённом прокси «Только правила с маршрутом» трафик идёт по указанному маршруту.
- RULE-07 Набор выбирается из выпадающего списка (только пользовательские наборы).
- RULE-08 Нажатие на существующее правило → «Изменить правило» с его значениями; «Сохранить» меняет правило (не дублирует); изменение действует на трафик сразу (без перезапуска защиты).
- RULE-09 «Удалить» в редакторе → правило исчезает, снэкбар «Rule deleted · Отменить»; «Отменить» возвращает его с тем же id и действием.
- RULE-10 «Отмена» и тап мимо диалога ничего не меняют.
- RULE-11 Правило в выключенном наборе показано бледным с пометкой «набор выключен»; правило страны/AS без базы GeoIP — с пометкой «нет базы».
- RULE-12 Маска: `*.example.com` блокирует `a.example.com`, но не `a.b.example.com` и не `example.com`; `**.example.com` — любую глубину; точное имя без «+ поддомены» не трогает поддомены.

## DEC — алгоритм решения (через интерфейс, проверка трафиком и причиной в журнале)

- DEC-01 Без правил всё разрешено.
- DEC-02 Глобальная блокировка домена с поддоменами: домен и поддомены заблокированы, DNS-ответ 0.0.0.0 (быстро), соседний домен проходит; в журнале причина — это правило.
- DEC-03 Более узкое разрешение побеждает более широкую блокировку в том же наборе.
- DEC-04 При равной узости побеждает блокировка.
- DEC-05 Правила приложения проверяются раньше глобальных внутри набора; правило группы действует на всех её участников.
- DEC-06 Первый включённый набор с решением побеждает; выключенный набор не участвует.
- DEC-07 Глобальное разрешение выше не снимает блокировку приложения в нижнем наборе.
- DEC-08 Блокировка «Всё» у приложения + исключение по домену: исключение проходит, остальное нет.
- DEC-09 Изменение порядка наборов (перетаскивание) меняет решение сразу.
- DEC-10 Правило по стране и по AS (при скачанных базах GeoIP) блокирует соответствующие адреса.
- DEC-11 Список блокировки: запись блокирует домен с поддоменами; `!запись` — исключение; `=запись` — только точное имя.
- DEC-12 Список с действием «Разрешить» работает как исключения.
- DEC-13 Блокировка по имени при обращении по IP (без DNS): решение по SNI в ClientHello.

## APPS — приложения и группы

- APPS-01 Список: группы сверху (имя, число приложений, число правил), затем приложения (иконка, имя, пакет, число правил/трафик); подзаголовок — число приложений.
- APPS-02 Поиск по имени и пакету.
- APPS-03 «⋮»: «Показывать системные» (галочка) добавляет системные; «Только с правилами» оставляет приложения с правилами; сортировка «По правилам / По имени / По трафику» (галочка у выбранной) меняет порядок.
- APPS-04 Нажатие на приложение → экран правил приложения: заголовок имя, подзаголовок «пакет · uid N»; чипы групп, куда входит приложение (нажатие → группа); кнопка «История (N)» → журнал с фильтром `pkg == "…"`.
- APPS-05 Нет правил → «No rules for this app…»; кнопка «Добавить правило» → RULE-02.
- APPS-06 Удалённое приложение → в списке приложений остаётся строка «<пакет> (не установлено)», пока у него есть правила; на его экране «This app is not installed», правила остаются и редактируются.
- APPS-07 «Новая группа» → ввод имени (пусто — OK неактивна) → открывается группа на вкладке «Участники».
- APPS-08 Группа: «Добавить приложения» → полноэкранный выбор с поиском и чипом «Системные», галочки, счётчик «N selected», кнопка «Добавить N» → участники в списке; крестик у участника удаляет его со снэкбаром «Отменить».
- APPS-09 Группа: вкладка «Правила (N)»; правило группы действует на всех участников (трафиком).
- APPS-10 Группа: «Переименовать» (карандаш) меняет имя везде; «⋮ → Удалить группу» удаляет её и её правила, снэкбар «Отменить» возвращает всё.

## GLOB — глобальные правила

- GLOB-01 Подзаголовок — число показанных правил; поиск по цели; чипы наборов фильтруют по набору (выбор одного, «Все наборы» снимает); чипы типов (Хосты, IP, AS, Страны, Весь трафик) и «Порты» фильтруют; повторное нажатие снимает чип.
- GLOB-02 «⋮»: «По имени» (внутри типа цели: сначала домены, затем адреса) / «Сначала новые» меняют порядок, галочка у выбранного.
- GLOB-03 Кнопка профиля «<профиль> ▾» открывает меню профилей (как HOME-14).
- GLOB-04 Пусто → «No global rules…».

## SEL — выделение правил (глобальные, приложение, группа)

- SEL-01 Долгое нажатие на правило выделяет его; заголовок «N selected»; нажатия добавляют/снимают выделение; «Назад» снимает выделение.
- SEL-02 «Переместить в набор» → правила переходят в выбранный набор (видно в подписи и в решении трафика).
- SEL-03 «Экспорт» → JSON только выделенных правил (импортируется обратно).
- SEL-04 «Удалить» → удаляет выделенные, снэкбар «N rules deleted · Отменить» возвращает их.

## SETS — наборы и профили

- SETS-01 Профили: радиокнопка у активного; нажатие на строку активирует профиль; подпись «N из M наборов включено».
- SETS-02 «Новый профиль из текущего» → имя → новый профиль с текущим порядком и выключателями становится активным.
- SETS-03 «⋮» у профиля: «Переименовать»; «Экспорт» (JSON профиля); «Удалить» (неактивно, если профиль один) → удалён, снэкбар «Отменить»; удаление активного переключает на первый оставшийся.
- SETS-04 Переключение профиля применяет его порядок и выключатели наборов, трафик решается по ним сразу; наборы, о которых профиль не знает, выключены.
- SETS-05 Наборы по приоритету: номер, имя, «N правил» или «Список · N записей», выключатель; выключатель меняет решение трафика сразу и сохраняется в активном профиле.
- SETS-06 Долгое нажатие и перетаскивание меняет порядок (и решение — DEC-09); доступно также действиями «Переместить выше/ниже» для TalkBack.
- SETS-07 «Новый набор» → имя → набор в конце, включён.
- SETS-08 Нажатие на набор → диалог: имя (переименование по «Сохранить»), экспорт JSON / hosts / домены (файлы верного формата с правилами набора), «Удалить набор» (не для «По умолчанию») с подтверждением «Delete “X” and its N rules?» → набор и его правила удалены.
- SETS-09 «⋮ → Экспорт всего (JSON)» → файл со всеми наборами, правилами, группами, профилями, который импортируется обратно без потерь.
- SETS-10 «⋮ → Импорт Packetwall JSON»: показывает, что в файле (наборы, правила, группы, профили, адреса списков для скачивания); «Добавить как новые наборы» — добавляет с самым низким приоритетом; «Заменить всю конфигурацию» (только для полного файла) — с подтверждением; после замены есть «Вернуть как было», которое восстанавливает прежнюю конфигурацию.
- SETS-11 Испорченный JSON → понятная ошибка, конфигурация не меняется.

## BL — списки блокировки

- BL-01 Подзаголовок «N включено · M записей»; пусто → «No lists yet…».
- BL-02 Каталог с чипами категорий; «+» у записи каталога добавляет список, он скачивается (строка «Обновление…» с индикатором, затем «N записей · дата»), исчезает из каталога; трафик к записи списка блокируется.
- BL-03 Ошибка скачивания (нет сети / 404 / неверный формат / ни одной записи в файле) → красная строка с понятной причиной, прежние записи остаются; повтор после восстановления исправляет. Адреса http:// тоже скачиваются.
- BL-04 Выключатель у списка включает/выключает его (трафик).
- BL-05 «Обновить все» (неактивно во время обновления или без списков с адресом) обновляет все списки.
- BL-06 «Добавить по адресу или из файла»: адрес должен начинаться с http(s):// и не повторять добавленный («Уже добавлен»); имя по умолчанию — хост; «Из файла» → выбор файла → импорт (IMPF-*).
- BL-07 Нажатие на список → экран записей (LIST-*); настройки списка (шестерёнка): имя, адрес, статистика, Блокировать/Разрешить, Reject, «Обновить сейчас», «Удалить» с подтверждением.

## LIST — записи списка и правки поверх него

- LIST-01 Вкладка «Записи»: поиск; показаны первые N, подсказка об этом; галочка у записи выключает её (запись перестаёт блокировать) — это правка.
- LIST-02 Вкладка «Мои правки (N)»: выключенные записи (кнопка «Вернуть»), добавленные (крестик удаляет); пометка «устарело», если записи больше нет в списке.
- LIST-03 «Добавить запись» — одна или несколько строк, проверка формата; добавленная запись блокирует трафик.
- LIST-04 Правки переживают обновление списка.
- LIST-05 «Сбросить правки» с подтверждением возвращает список к исходному.

## IMPF — импорт сторонних форматов

- IMPF-01 Формат определяется автоматически (чип «Авто: <формат>»); можно выбрать вручную: hosts, uBO/AdGuard, PCAPdroid, NetGuard, AFWall+, RethinkDNS, sing-box, Packetwall.
- IMPF-02 План: «Правил N · записей M · пропущено K», примечания (что не поддерживается), примеры пропущенных строк.
- IMPF-03 Имя (по умолчанию — имя файла), Блокировать/Разрешить для записей; «Импорт» создаёт наборы с самым низким приоритетом («New sets created: N»); правила действуют на трафик.
- IMPF-04 Для каждого формата — реальный образец файла: правила и записи совпадают с ожидаемыми.
- IMPF-05 Файл Packetwall JSON уходит в SETS-10; испорченный/двоичный/слишком большой файл — понятная ошибка, без падения.

## CAP — вкладка «Захват» журнала: буфер, сохранение, трансляция, запись

- CAP-01 Буфер: «N пакетов · объём · из M МБ · вытеснено K» — растёт с трафиком; без хранения пакетов — «Packet capture is off», кнопки неактивны.
- CAP-02 «Сохранить» → файл `packetwall-<дата>.pcapng` в «Анализе файлов», тост «Saved»; файл открывается и содержит пакеты.
- CAP-03 «Экспорт» → системный диалог сохранения; сохранённый файл — корректный pcapng с пакетами буфера.
- CAP-04 Трансляция: выключатель запускает сервер на 127.0.0.1:57012 (строка «… клиентов: N»); `adb forward` + подключение получает поток pcapng (заголовок SHB, затем пакеты трафика); «по Wi-Fi» — слушает на адресе сети, без токена соединение отклоняется, с токеном — принимается; «Новый токен» меняет токен (старый больше не принимается); «Как подключиться» открывает лист с вкладками USB/Wi-Fi и кнопками копирования. Во время паузы поток не получает новых пакетов. Ушедшего клиента сервер замечает на следующей записи пакетов: счётчик клиентов уменьшается, когда идёт трафик.
- CAP-05 Запись на диск: при включении — строка «пишется в <файл>»; при достижении размера файл сменяется новым; хранится не больше K файлов; файлы видны в «Анализе файлов». Без хранения пакетов выключатель недоступен с пояснением.
- CAP-06 Кнопка «Файлы (N)» → «Анализ файлов».

## FILE — анализ файлов

- FILE-01 «Выбрать файл» → системный выбор файла; pcap/pcapng открывается: заголовок — имя файла, подзаголовок «N пакетов · M соединений»; файл попадает в «Недавние» с датой и числом пакетов (максимум 10, без повторов, последний сверху).
- FILE-02 Вкладка «Соединения»: строки как в журнале, фильтр-выражение работает (как LOG-06), ошибка выражения подсвечивается; нажатие → экран соединения с вкладками пакетов/данных/HTTP из файла.
- FILE-03 Вкладка «Пакеты»: все пакеты файла по порядку с относительным временем; нажатие → экран пакета.
- FILE-04 Обрезанный файл → красная строка «файл обрезан, прочитано N пакетов»; нераспознанные пакеты → «пропущено N»; не pcap → понятная ошибка в карточке, приложение не падает.
- FILE-05 «Записи Packetwall»: сохранённые и записанные файлы (размер, дата); нажатие открывает; «Сохранить» — экспорт копии; «Удалить» с подтверждением удаляет файл.
- FILE-06 Нажатие на недавний файл открывает его снова (разрешение на чтение сохраняется после перезапуска).
- FILE-07 После перезапуска процесса открытый файл не в памяти — экран файла возвращает назад без падения.

## PKT — экран пакета

- PKT-01 Слои разобраны: кадр/IP/TCP|UDP|ICMP/DNS/TLS/HTTP с полями; узлы раскрываются; hex-дамп с ASCII.
- PKT-02 Пакет вытеснен из буфера → «The packet is no longer in the buffer».

## SRCH — поиск

- SRCH-01 Пусто → подсказка; чипы «Всё / Правила / Списки / Приложения / Соединения» с числом найденного после ввода.
- SRCH-02 Правила: цель (с маской, свойства порта/протокола), где живёт («для кого · в наборе X · в профилях …» / «набор выключен» / «не в профилях» / «сейчас выключен»), бледные — в выключенном наборе; нажатие → экран правил владельца (приложение/группа/глобальные).
- SRCH-03 Списки: имя, «N совпадений: примеры» (поиск по записи и по родительскому домену хоста, без выключенных записей, с добавленными); нажатие → список, открытый на этой записи (если совпала только добавленная вручную запись — на вкладке «Мои правки»). Запросы короче 2 символов списки не ищут.
- SRCH-04 Приложения: по имени и пакету, с числом правил; нажатие → правила приложения.
- SRCH-05 Соединения: по хосту, IP, имени и пакету приложения, последние 100, «приложение · время · заблокировано/разрешено»; нажатие → экран соединения.
- SRCH-06 Ничего не найдено (во всём или в выбранном чипе) → «Nothing found».

## STAT — статистика

- STAT-01 Сводка: отправлено, получено, запросов, DNS — совпадают с журналом и фактическим трафиком.
- STAT-02 График скорости: текущая ↑/↓ и максимум; на паузе — «на паузе с ЧЧ:ММ» и пунктир.
- STAT-03 «Топ приложений» по убыванию трафика с ↑/↓; нажатие → журнал `pkg == "…"`.
- STAT-04 «Топ хостов» (число соединений · байты); нажатие → журнал `host == "…"`.
- STAT-05 «Протоколы» с числом; нажатие → журнал `proto == "…"`.
- STAT-06 «Трекеры по приложениям» (при скачанной базе) → журнал `tracker && pkg == "…"`.
- STAT-07 «Заблокировано по приложениям» → журнал «Заблокированные» с `pkg == "…"`.
- STAT-08 Пустые разделы не показываются.

## SET — настройки (каждая настройка сохраняется после перезапуска процесса)

- SET-01 Тема: см. APP-06.
- SET-02 «Хранить пакеты» выкл → после перезапуска защиты пакетов нет (CONN-05, CAP-01), кнопки «Пауза» нет (HOME-03), «Запись на диск» недоступна; вкл → пакеты есть.
- SET-03 Размер буфера N МБ → «из N МБ» в буфере; при переполнении растёт «вытеснено».
- SET-04 Обрезка пакета (полный / 1514 / 512 / 128 Б) → сохранённые пакеты не длиннее выбранного (caplen в pcapng).
- SET-05 Подсказка «Изменения применяются при следующем включении защиты» — и это правда: до перезапуска защиты действует старое значение, после — новое.
- SET-06 Постоянная VPN: строка открывает настройки VPN Android; состояние — см. APP-08, SYS-10.
- SET-07 «Обход локальной сети» вкл → трафик к 192.168/10/172.16 идёт мимо VPN (в журнал не попадает); выкл → через VPN.
- SET-08 Прокси (SOCKS5/HTTP CONNECT): выключатель, режимы «Весь трафик» / «Только правила с маршрутом», хост, порт (ошибка при неверном, сохраняется только верный), логин/пароль; «Проверить» → «TCP N мс · IP … · UDP N мс» или «✕ причина»; статус «Прокси доступен/недоступен» (+ «UDP ✓»). Трафик реально идёт через прокси (прокси видит соединения, в журнале маршрут «Прокси»).
- SET-09 UDP через прокси: «Блокировать» (UDP не проходит, причина в журнале), «Через прокси» (только SOCKS5, проходит через UDP ASSOCIATE), «Напрямую»; при переключении на HTTP CONNECT режим «Через прокси» меняется на «Блокировать».
- SET-10 При недоступном прокси: «Kill switch» — всё, что шло бы через прокси, блокируется и в журнале помечено заблокированным с причиной kill switch (TCP, UDP и DNS-запросы, которые получают ответ 0.0.0.0, чтобы приложения не ждали); «Напрямую» — идёт мимо прокси. После возвращения прокси трафик снова через него.
- SET-11 «Приложение-прокси»: выбор приложения (только настоящие приложения, uid ≥ 10000, без самого Packetwall); его собственный трафик не отправляется в прокси (не петля), но фильтруется; «Нет» сбрасывает.
- SET-12 DNS: «Системный» / «DNS-over-HTTPS»; пресеты и свой адрес (только https://, иначе ошибка и не сохраняется); при работающем DoH — строка «Запросов N · ошибок M · среднее K мс» растёт с запросами; DNS-запросы Shell решаются через DoH (в Главной «DoH <хост>»).
- SET-13 GeoIP: «Скачать» → «Загрузка…» → «Загружено: страны <сборка>, N МБ / AS …»; правила стран/AS начинают действовать (RULE-11 пометка исчезает); «Удалить» с подтверждением (число затронутых правил) → снова «не скачано»; ошибка сети — красным.
- SET-14 Трекеры: «Скачать» → «N доменов · дата»; соединения к трекерам помечены (LOG-06 `tracker`, CONN-02); «Удалить» с подтверждением.
- SET-15 Расписание: «Автообновление списков» (и «только по Wi-Fi» при включённом) ставит фоновую задачу.
- SET-16 Резервная копия: «Выбрать папку» → системный выбор папки → «Папка: X · последняя: —»; «Сделать сейчас» → файл в папке, тост «Backup saved», время последней обновилось; хранятся последние 7; «Выключить» убирает папку; копия импортируется (SETS-10).
- SET-17 Журнал: «Хранить: текущий сеанс / 1 / 7 / 30 дней»; уменьшение срока спрашивает подтверждение («Отмена» ничего не меняет); «Только заблокированные» и «Очистить сохранённый журнал» с подтверждением — см. LOG-20.
- SET-18 Значки «i» у настроек открывают справку с заголовком и текстом.

## LEAK — нет утечек реального адреса через прокси (вышестоящий прокси, «весь трафик»)
- LEAK-01 SOCKS5 (без входа и со входом) и HTTP CONNECT: каждая строка журнала либо прошла через прокси, либо заблокирована, либо DNS-запрос к DNS VPN, отвеченный через DoH-прокси; прямых соединений нет. Прокси на хосте видит соединения приложений.
- LEAK-02 DNS: имена разрешаются через DoH (1.1.1.1:443) поверх прокси, а не обычным DNS сети.
- LEAK-03 UDP (по умолчанию «Блокировать»): UDP к внешнему серверу заблокирован (приложения переходят на TCP); прямо не уходит.
- LEAK-04 Ping: ответ приходит после проверки TCP через прокси; ICMP наружу не отправляется (строка помечена как через прокси).
- LEAK-05 Собственные загрузки Packetwall (списки, базы GeoIP и трекеров) идут через тот же прокси, имя хоста разрешает прокси (в журнале прокси — имя, не адрес); адреса локальной сети при обходе LAN — напрямую.
- LEAK-06 Прокси недоступен, «аварийный выключатель»: ни TCP, ни UDP, ни ping не уходят напрямую; собственные загрузки Packetwall завершаются ошибкой; после выключения защиты снова идут напрямую.
- LEAK-07 Пауза: в журнал ничего не пишется, но трафик идёт тем же путём — через прокси; ping отвечается через проверку, UDP по-прежнему не уходит.

## Как запускать и что не покрыто

- `tools/e2e/run-instrumented.sh [Класс[#тест] …]` — эмулятор с интернетом, запускает `tools/e2e/host.py`
  (списки-фикстуры, тестовые SOCKS5/HTTP-прокси с журналом, `adb forward` для трансляции) и Gradle.
- `python3 tools/e2e/coverage.py` — какие пункты имеют тест (`@Covers`), какие покрыты только сценариями с root
  (`tools/e2e/e2e.py`: GeoIP-правила, приложение-прокси с реальным трафиком, перезагрузка с постоянной VPN), какие ни одним.
- Без автоматического теста: SYS-09 (обновление APK при постоянной VPN), FILE-07 (перезапуск процесса убил бы и
  тест), ротация файлов записи в CAP-05 (минимальный размер файла 8 МБ). SYS-08 играет второй VPN-клиент из тестового
  APK (OtherVpn); PKT-02 вытесняет пакеты загрузкой /zeros с хоста.
  UDP-reject (ICMP unreachable) не реализован; ICMP не привязывается к uid приложения (поэтому QR-08 проверяется на ping).
