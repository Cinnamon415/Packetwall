# Форк PCAPdroid: «файрвол + мини-Wireshark» — предложение

База: upstream `emanuele-f/PCAPdroid` @ `6c0e02dc` (2026-11-12, v2.0.2).
У каждого пункта есть ID (например, `R7`), чтобы выбирать по номерам. Оценка трудоёмкости: **S** — до дня, **M** — несколько дней, **L** — неделя и больше.
`#123` — номер issue в upstream, где об этом просили.

---

## 0. Что есть сейчас (по коду)

**Модель правил** (`MatchList`/`Blocklist`, native `blacklist.c`, `pcapdroid.c`):
- Типы правил: `APP` (uid/пакет), `HOST`, `IP`/CIDR, `COUNTRY`, `PROTOCOL` (последний используется только в фильтрах, не в файрволе).
- **Уже есть** зачаток исключений: per-app allowlist. Можно заблокировать приложение и разрешить ему конкретные хосты/IP (пункт меню «Разрешить для приложения…»).
- Порядок проверки жёстко зашит в код:
  1. глобальные блокировки IP, домена и страны;
  2. блокировка приложения минус его allowlist;
  3. whitelist-режим (блокировать всё, кроме приложений из списка).

  Исключений из глобального правила нет. Нельзя сделать «блокировать `*.example.com`, кроме `api.example.com`» или «запретить домен только для приложения X».
- Домены сравниваются точно или по 2-му уровню; поддомены 3-го уровня не покрываются, `co.uk` обрабатывается неправильно. Нет масок, портов, TCP/UDP, типа сети, расписания, срока действия, приоритетов, комментариев, счётчиков срабатываний.
- Заблокированные TCP-пакеты **молча выбрасываются**, приложению не отправляется RST. Отсюда таймауты на 10+ секунд. Для DNS отдаётся подменённый ответ, это хорошо.
- Имена хостов берутся из DNS (кэш ip→host) и SNI. При системном «Частном DNS» остаётся только SNI.

**Интерфейс правил:** плоский список (`EditListFragment` + `ListEditAdapter`) с вкладками «Блокировки» / «Белый список». Нет поиска, сортировки, разделов по типам, массовых операций и редактора правила.

**Импорт/экспорт:** JSON `{"rules":[{"type","value","allowlist"?}]}`, слияние или замена. Нет форматов hosts/списков/AdGuard, нет подписок, нет предпросмотра.

**Анализ трафика:** соединения, payload (текст/hex), HTTP-лог, HAR, чтение pcap/pcapng, TLS-расшифровка через mitm-аддон, дамп в файл / HTTP-сервер / UDP-экспортёр.

## 1. Движок правил (ядро) — главное

| ID | Предложение | Оценка |
|---|---|---|
| **R1** | **Единая модель правила**: `действие` (BLOCK / ALLOW / LOG-only) × `кому` (все, приложение(я), uid, системные uid, Unknown) × `куда` (хост, IP/CIDR, порт/диапазон, TCP/UDP/ICMP, L7-протокол nDPI, страна, ASN) × `условия` (тип сети, SSID, роуминг, расписание, срок действия) + `вкл/выкл`, `комментарий`, `теги`, `источник` (вручную / подписка / импорт), `создано`, `счётчик срабатываний` и `последнее срабатывание`. | L |
| **R2** | **Разрешение конфликтов «конкретное побеждает общее»**: `хост > домен > IP > CIDR > страна/ASN > приложение > политика по умолчанию`; правило с условием сильнее правила без условия; ручной приоритет для особых случаев. Это даёт нужное: «запретить приложение → разрешить ему `api.example.com`», «запретить `*.example.com` → разрешить `cdn.example.com`», «разрешить всем, но запретить домен только приложению X». Альтернатива — упорядоченный список с первым совпадением, как в iptables. См. вопросы. | L |
| **R3** | **Правильные домены**: точное совпадение (`=api.example.com`), «домен и все поддомены» (`example.com` / `*.example.com`, на любой глубине), список публичных суффиксов (`co.uk`, `com.ru`, `github.io`), опционально regex. Native: suffix-trie вместо поиска в hash-таблице. | M |
| **R4** | **Порты и протоколы**: `tcp/443`, `udp/53`, `udp/*` (например, запретить QUIC приложению), диапазоны. #300 | M |
| **R5** | **Reject вместо drop**: TCP RST / ICMP unreachable / DNS NXDOMAIN (или `0.0.0.0`). Приложение сразу получает отказ и не висит на таймауте (тот самый случай с `rtb-s2p`). Выбор глобально и для каждого правила. | M |
| **R6** | **Политика по умолчанию для каждой сети**: Wi-Fi / мобильная / роуминг / VPN / конкретный SSID → «разрешить всё» / «запретить всё» (whitelist) / «спросить». Как в NetGuard и AFWall. | M |
| **R7** | **Временные правила**: «разблокировать хост или приложение на 10 мин / 1 ч / до перезагрузки / до выключения экрана»; «заблокировать до…». Сейчас временно можно разблокировать только приложение. #226 #247 | S–M |
| **R8** | **Расписание**: правило действует в заданные часы и дни (например, ночью соцсетям нет сети). | M |
| **R9** | **Профили** (наборы правил: «Дом», «Работа», «Строгий»), переключение вручную, по сети, по расписанию или через intent/Tasker. #387 | M |
| **R10** | **Интерактивный режим «спросить»**: уведомление с кнопками «Разрешить / Запретить / На 1 час», когда приложение впервые выходит в сеть (и опционально при каждом новом домене этого приложения). Соединение держится несколько секунд, пока вы не ответите. | L |
| **R11** | **Системные UID как сущности**: Unknown(-1), netd/DNS, root(0), system(1000), phone(1001), media… Их можно блокировать и разрешать отдельно, с понятными подписями, какие пакеты входят в общий uid. #382 #590 | S |
| **R12** | **Блокировка до SNI**: если имя заранее неизвестно (общий IP), держать соединение до ClientHello и решать уже по SNI, а не по IP. Защищает от «заблокировал опросы — отвалились покупки на том же IP». | M |
| **R13** | **«Почему заблокировано»**: в каждом соединении хранится id сработавшего правила и цепочка решения; в деталях соединения — «Заблокировано правилом #12 (`*.tbank.ru`, профиль Дом)», с переходом к правилу. | S–M |
| **R14** | **Анализ правил**: «правило перекрыто другим», «дубликат», «не срабатывало 30 дней», «конфликт ALLOW/BLOCK одной специфичности». | M |
| **R15** | **LAN, multicast, IPv6**: отдельные переключатели «локальная сеть» и «bogon» для каждого приложения; корректная работа в сетях только с IPv6. #168 #223 | M |
| **R16** | **Встроенный зашифрованный DNS** (DoH/DoT к выбранному серверу, например AdGuard). Системный «Частный DNS» можно выключить: трафик остаётся зашифрованным, а PCAPdroid видит имена и может блокировать по DNS. Сейчас upstream шлёт обычный DNS на 9.9.9.10. | M |
| **R17** | **Блокировка на уровне DNS** (как AdGuard DNS): заблокированный домен сразу получает `0.0.0.0` / NXDOMAIN — быстро и без лишних соединений. | S (поверх R16) |
