## 2. Модель правил

### 2.1 Оси
- **Кто:** `Глобально` → `Группа приложений` → `Приложение` (+ системные uid: Unknown, netd/DNS, root, system…).
- **Куда** (от широкого к узкому): `Всё` → `Страна` → `ASN` → `CIDR` → `IP` → `домен` → `поддомен` → … → `точный хост` → *(позже: маршрут/URL-путь, только для расшифрованного трафика)*.
  - Имя точнее IP.
  - Порт и протокол (`tcp/443`, `udp/*`) уточняют любое назначение.

### 2.2 Синтаксис имён
- Свои маски: `*` = любые символы **внутри одного уровня** (не переходит через точку), `**` = любая глубина.
- Флаг **«включая поддомены»** у правила на домен.
- Без regex.
- Маска считается шире точного имени той же глубины.

### 2.3 Наборы правил (rule sets)
- Правило всегда лежит в наборе. Без явного выбора оно попадает в **default** (приоритет 1, самый высокий).
- Наборы включаются и выключаются; порядок значимости меняется **перетаскиванием**.
- Импорт из сторонних форматов создаёт **отдельный набор с минимальным приоритетом**.
- **Профиль** = сохранённый снимок «какие наборы включены и в каком порядке»; переключается одним нажатием, с плитки и через виджет.
- **Условий нет** — ни у правил, ни у наборов: никакой сети/SSID, расписания, экрана/фона. Набор просто включён или выключен; переключение — вручную или профилем. *(решение 2026-11-14)*
- **Временных ограничений нет** совсем: ни временных правил, ни «разблокировать на N минут», ни расписаний.

### 2.4 Режим работы
- Один режим: **всё разрешено, кроме того, что запрещено правилами.** Режим whitelist («всё запрещено») убран *(решение 2026-11-14)*.
- «Запретить приложению всё» — обычное правило приложения с типом «Всё» (создаётся через «+ правило»); отдельной «политики в наборе» в интерфейсе нет.
- Никаких самостоятельных блокировок: без правил трафик не трогается. Нет «блокировать новые приложения», нет режима «спросить».

### 2.5 Алгоритм решения
1. Наборы перебираются по приоритету (1 → N), только включённые. **Первый набор, давший решение, побеждает.**
2. Внутри набора сначала правила приложения (приложение → его группы), потом глобальные. Побеждает самое узкое «куда»; при равенстве — блокировка.
3. Политика приложения «всё разрешить / всё запретить» — обычное правило «приложение → всё» внутри набора.
4. Глобальное **разрешение** только снимает глобальные блокировки; оно не открывает то, что приложению запрещено в каком-либо наборе (поиск продолжается по нижним наборам только среди правил приложения).
5. Решения нет → соединение разрешено.
6. В соединении хранится id сработавшего правила, его набор и профиль, чтобы показать «почему заблокировано».

### 2.6 Действие блокировки
- По умолчанию **drop**, как сейчас; у правила и набора можно выбрать **reject**: TCP RST / ICMP unreachable / DNS NXDOMAIN.
- DNS-запрос к заблокированному домену получает подменённый ответ.
- Если имя заранее неизвестно (общий IP), соединение ждёт ClientHello и решение принимается по SNI.

### 2.7 DNS
- Встроенный DoH/DoT к выбранному серверу (AdGuard, Quad9, Cloudflare, свой). Системный «Частный DNS» можно выключить и при этом видеть имена.
- Блокировка на уровне DNS для заблокированных доменов.

## 2.8 Upstream-цепочка (вариант A, решение 2026-11-15)
Packetwall остаётся VPN-файрволом, но разрешённый трафик может уходить не напрямую, а в локальный или удалённый прокси (например sing-box, v2rayNG, FlClash в режиме «только прокси», без своего VPN).
- **Протоколы:** SOCKS5 (TCP + UDP через UDP ASSOCIATE) и HTTP CONNECT (только TCP). Хост, порт, логин и пароль.
- **Приложение-прокси** исключается из VPN Packetwall (`addDisallowedApplication`), чтобы его исходящий трафик не возвращался в петлю; собственные сокеты Packetwall защищаются `VpnService.protect()`.
- **UDP/QUIC через upstream** — включается отдельно (для HTTP CONNECT невозможно: UDP идёт напрямую).
- **DNS через upstream** — встроенный DoH не уходит мимо прокси.
- **Если upstream недоступен:** блокировать (kill switch) или пускать напрямую.
- **Проверка соединения:** задержка, внешний IP, работает ли UDP.
- Фильтрация, логи и анализ пакетов работают до отправки в upstream, поэтому ничего не теряется. В обзоре соединения есть поле «Маршрут».
- Реализация опирается на уже имеющуюся в `zdtun` пересылку соединений в SOCKS5.
- **Позже:** маршрут как действие правила (разрешить напрямую / через upstream), встроенный WireGuard или ядро sing-box.

## 3. Импорт / экспорт / фильтры
- **Фильтры (подписки):** набор привязан к URL списка, автообновление по расписанию (можно только по Wi-Fi), встроенный каталог (HaGeZi, OISD, AdGuard, RU-списки), свои URL. Вкладка «Фильтры», выключатели, «Обновить все».
- **Импорт:** окно выбора исходного формата → конвертация в свой формат с отчётом о пропущенном. Форматы:
  - hosts, простые списки доменов, CIDR-списки;
  - сетевые правила uBO/AdGuard (`||x^` → домен с поддоменами, `@@` → разрешение, `$app=` → приложение, `$important` → наверх набора; остальное — в отчёт);
  - экспорты PCAPdroid, NetGuard, AFWall+, RethinkDNS, sing-box rule-set.
- **Экспорт:** свой JSON (версионированный, без потерь), hosts, список доменов, CSV; весь набор / профиль / выбранное.
- **Автобэкап** правил и настроек в выбранную папку по расписанию.

## 7. Реализация M1 — уточнения (2026-11-15)
- **Движок правил** — `app/src/main/jni/core/pw_rules.c`. Kotlin компилирует включённые наборы в текстовый файл (`RulesCompiler.kt`), движок подменяется на лету, активные соединения пересчитываются. Литеральные домены лежат в хеш-таблице: 300 тыс. записей грузятся за ~0,1 с, занимают ~22 МБ, проверка соединения ~0,1 мкс.
- **Маски:** `*` — любые символы внутри одного уровня, `**` — один и более уровней (сам домен не включает; для него есть «+ поддомены»).
- **Узость «куда»:** точный хост > `*.x` > `x + поддомены` > `**.x` > IP/CIDR (по длине префикса) > страна > всё; порт и протокол добавляют узости. При равенстве побеждает блокировка.
- **DNS-запросы от netd/неизвестного uid:** применяются только глобальные правила; если какое-либо правило приложения или группы разрешает имя, ответ не подменяется — решение принимается уже по соединению с настоящим uid. Заблокированный запрос получает ответ 0.0.0.0/::.
- **Блокировка посреди потока** (по SNI/HTTP Host) — TCP всегда получает RST, иначе клиент зависает до таймаута. Новые соединения по умолчанию drop, reject — по правилу.
- **Private DNS:** в режимах «выкл.» и «автоматически» DoT к адресам DNS внутри VPN отбрасывается, и Android переходит на обычный DNS, который видит файрвол. В строгом режиме на главной показывается предупреждение: имена не видны, работают только правила по SNI.
- **Профили следуют за живой конфигурацией:** переключение и перестановка наборов правят активный профиль; в остальные профили новые наборы добавляются выключенными.
- **Формат списков** (`files/lists/<id>.txt`): одна запись на строку, `!` — противоположное действие, `=` — точный хост, без префикса — домен с поддоменами; IP/CIDR как есть. Конвертер понимает hosts, простые списки, сетевые правила uBO/AdGuard (`||x^`, `@@`, `$important`), dnsmasq и IP/CIDR. Остальное (косметика, `$app=`, пути URL, regex) идёт в отчёт о пропущенном.
- **Отложено:** автообновление списков по расписанию (M3, вместе с автобэкапом); страны и ASN (нужна база GeoIP, M3); импорт форматов NetGuard, AFWall+, RethinkDNS, sing-box и PCAPdroid; исключение по домену внутри блокировки по IP работает, только если имя было видно в DNS до соединения.

## 8. Реализация M2 — уточнения (2026-11-15)
- **Буфер пакетов.** Нативный дампер PCAPdroid пишет pcapng с расширениями: блоки uid → приложение и комментарий `u-<uid>` у каждого пакета. Kotlin (`analysis/PacketStore.kt`) держит кольцевой буфер в памяти (по умолчанию 16 МБ, 4–128 МБ в настройках, есть snaplen) с индексом по соединениям. Экспорт — простая склейка блоков, поэтому Wireshark видит приложение у каждого пакета.
- **Дополнения в дампе:** опция EPB flags с направлением пишется и в VPN-режиме; пакеты, отброшенные файрволом, тоже попадают в дамп с комментарием `dropped`. Это крестики на шкале.
- **Вкладки соединения:**
  - «Пакеты» — шкала (высота — log размера, цвет — направление, ✕ — drop; ведение пальцем выделяет диапазон, нажатие сбрасывает) и список в две строки с относительными seq/ack;
  - «Данные» — блоки ↑/↓ без ретрансмиссий, режимы Авто/Текст/Hex;
  - «HTTP» — разобранные запрос и ответ, для TLS — SNI/ALPN, для QUIC — пометка «зашифровано».
- **Экран пакета:** дерево (IPv4/IPv6, TCP/UDP/ICMP, DNS, TLS ClientHello, HTTP, заголовок QUIC) и hex по 8 байт в строке без горизонтальной прокрутки; выбранное поле подсвечивается в hex.
- **Логи:** вкладки DNS (соединения с L7 DNS), HTTP (запросы открытым текстом) и Захваты (сохранить буфер в файл, экспорт через системный диалог, удаление).
- **Фильтр логов** (`analysis/ConnFilter.kt`): поля app, pkg, uid, host, ip, port, proto, bytes, sent, rcvd, blocked, allowed, active; операторы `== != ~ !~ < <= > >=`, `&& || !` (или and/or/not) и скобки. Строка без операторов — обычный поиск. Ошибка разбора подсвечивается под полем.
- **Статистика:** график скорости ↑/↓ (последние ~10 минут), приложения по трафику, хосты, протоколы, блокировки по приложениям.
- **Цвета:** ↑ янтарный, ↓ синий (ExtraColors.up/down), красный только для блокировок.
- **Хранение:** пока только текущая сессия в памяти; постоянная база (SQLite, N дней) переносится в M3.
- **Отложено:** JA3/JA4 и сертификат TLS, метки трекеров, ASN, трансляция pcap-over-IP/sshdump, кольцевой буфер на диске.

## 9. Реализация M3 — уточнения (2026-11-15)
- **Плитка быстрых настроек** (вкл/выкл, профиль в подзаголовке) и **виджет** (кнопка питания, нажатие на имя профиля переключает на следующий). Если нужно согласие на VPN, открывается приложение.
- **Packetwall исключён из своего VPN** (`addDisallowedApplication`): его собственные запросы (DoH, загрузка списков, GeoIP) идут напрямую, без петли.
- **Встроенный DoH:** локальный UDP-прокси на 127.0.0.1, на который движок перенаправляет DNS вместо системного сервера (порт DNAT настраивается). Клиент — OkHttp с HTTP/2: Quad9 не принимает HTTP/1.1. Пресеты по IP-адресам (Cloudflare, Quad9, Google, AdGuard) и свой URL. При DoH IPv6-DNS в VPN не объявляется. Заблокированные имена отвечаются локально ещё до прокси. Сбой сервера — SERVFAIL сразу, без таймаута.
- **Upstream (вариант A, первая версия):**
  - SOCKS5 средствами zdtun: TCP через прокси, логин и пароль поддерживаются;
  - zdtun не умеет UDP ASSOCIATE, поэтому UDP по выбору блокируется (QUIC откатывается на TCP) или идёт напрямую;
  - приложение-прокси исключается из VPN;
  - проверка доступности каждые 10 с; если прокси недоступен — kill switch или напрямую;
  - кнопка «Проверить» показывает задержку TCP и внешний IP через прокси;
  - DoH тоже идёт через прокси, если не задан логин;
  - в обзоре соединения есть поле «Маршрут».
- **Расписания (WorkManager):** ежедневное обновление блок-листов (только при заряженной батарее, по выбору только Wi-Fi) и ежедневный бэкап JSON в выбранную папку (SAF), хранятся последние 7 копий.
- **GeoIP:** DB-IP Country Lite (CC BY 4.0, ~8 МБ) скачивается по кнопке; читалка MMDB своя (`analysis/MmdbReader.kt`), с LRU-кешем. Правила «Страна» срабатывают, страна видна в поле «Назначение».
- **Постоянный журнал:** SQLite, хранение 1/7/30 дней или только сессия; закрытые соединения пишутся сразу, после перезапуска последние 5000 видны в логах.
- **Отложено:** HTTP CONNECT и UDP через upstream (нужна доработка zdtun), ASN, свой WireGuard/ядро sing-box, маршрут как действие правила.

## 10. Закрытие отложенного (2026-11-16)
- **ASN** — цель правила «AS13335». Префиксы AS раскрываются при компиляции из DB-IP ASN Lite (один обход дерева, кеш на диске). Тип `S` в движке ставит их по узости между страной и CIDR. AS и организация видны в карточке соединения.
- **Импорт** с выбором формата (автоопределение) и отчётом о пропущенном:
  - PCAPdroid: экспорт списка и полный бэкап; allowlist приложения → разрешения;
  - NetGuard XML: «Wi-Fi и мобильная» → блокировка; режим «блокировать по умолчанию» разворачивается в блокировки установленных несистемных приложений; `<filter>` → IP-правила приложения;
  - AFWall+ v1/v2, режимы allow/block;
  - RethinkDNS `.rbk` (SQLite: CustomDomain, CustomIp, AppInfo);
  - sing-box rule-set JSON; для `.srs` — подсказка про `rule-set decompile`;
  - uBO/AdGuard: `$app=` → правила приложения, `$important` → набор выше списка.

  Сеть-зависимые правила (только Wi-Fi или только мобильная) не переносятся — так требует принцип «без условий», они попадают в отчёт.
- **Метки трекеров:** AdGuard companiesdb (CC BY-SA 4.0), скачивается по кнопке. Метка показывается в логах, обзоре, статистике и фильтре (`tracker`, `tracker ~ google`).
- **TLS:** JA3 и JA4 (совпадают с Wireshark на тестовых векторах), предложенные и выбранная версии, шифр, сертификат до TLS 1.2 включительно (в TLS 1.3 он зашифрован).
- **Трансляция на ПК:** pcap-over-IP, по умолчанию только 127.0.0.1 (`adb forward`), LAN включается отдельно с предупреждением. **Непрерывная запись** — кольцо файлов pcapng по размеру и времени.
- **Upstream:**
  - HTTP CONNECT с Basic-авторизацией;
  - UDP через SOCKS5 UDP ASSOCIATE: ассоциацию держит приложение, relay задаётся движку;
  - режимы UDP: напрямую / блокировать / через прокси; kill switch распространяется и на UDP;
  - DoH идёт через HTTP-прокси (с логином) и SOCKS5 (без логина);
  - доработка zdtun — локальный коммит в субмодуле и `patches/zdtun-http-connect-udp-relay.patch`.
- **Маршрут как действие правила:** у разрешающего правила «напрямую» или «через upstream». Режим upstream «только правила с маршрутом» — выборочное проксирование.
- **Прочее:**
  - стрелки к соседним соединениям;
  - исключение из лога предлагает набор не ниже блокирующего и предупреждает о бесполезных вариантах;
  - сортировка и трафик в «Приложениях», фильтр «Порты»;
  - множественный выбор правил (перенос, экспорт, удаление), экспорт профиля;
  - CSV и pcapng отфильтрованного журнала;
  - ответы во вкладке DNS, журнал «только блокировки», график скорости на главной.
- **Исправлено по итогам e2e:** блокировка Private DNS отбрасывала весь трафик к известным DNS-серверам на любом порту (HTTPS к 1.1.1.1, DoH приложений). Теперь только DoT (853).
- **Тесты:** 21 юнит-тест, хостовый тест движка, `tools/e2e` — 33 проверки на эмуляторе.
- **Не сделано (вне возможностей без root или явно «позже»):** root-бэкенд; встроенные WireGuard и ядро sing-box; расшифровка TLS (MITM); sshdump. Проверка в Waydroid не завершена: у контейнера нет сети, `waydroid shell` требует sudo.

## 11. Waydroid и adb по сети (2026-11-17)
- **«Локальная сеть мимо VPN»** (настройка, по умолчанию выкл.): 10/8, 172.16/12, 192.168/16, link-local и multicast маршрутизируются мимо туннеля. Маршруты считаются вычитанием диапазонов (`engine/Routes.kt`, 40 маршрутов), так что `excludeRoute` из API 33 не нужен; собственный /30 VPN с DNS остаётся внутри. Без этой настройки VPN обрывает adb по Wi-Fi: Android закрывает существующие сокеты, и ответы уходят в туннель.
- **Waydroid:** в LXC-контейнере `rp_filter=1`. Входящие пакеты не получают метку сети (connmark), поэтому обратный поиск для uid 0 идёт в таблицу VPN, и ответы на `eth0` отбрасываются (растёт счётчик `TcpExt.IPReversePathFilter`). Это ломает любой VPN в Waydroid. Лечится только на хосте: `rp_filter=2` (loose) в контейнере.
- **e2e на устройствах без root и без `run-as`:** debug-сборка содержит `TestConfigActivity` (только `src/debug`), которая принимает конфигурацию через intent. Защита включается и выключается через `MainActivity` (`TOGGLE_ON` / `TOGGLE_OFF`), VPN определяется по `tun0`. `HOST=192.168.240.1` для Waydroid.
- **adb по сети рвётся при каждом включении и выключении VPN** даже с «Локальной сетью мимо VPN»: Android уничтожает сокеты затронутых приложений, и на секунду устройство становится `offline`. Команда, отправленная в этот момент, теряется. Из-за этого на Waydroid сценарии e2e падали через раз (новая конфигурация не доходила, и проверялись правила предыдущего сценария). `tools/e2e/e2e.py` теперь повторяет команду после переподключения.
- **Сервис сам вызывает `VpnService.prepare()`:** после обновления приложения или запуска с плитки и виджета без этого `establish()` молча возвращал `null` (нашлось на e2e после рефакторинга 0.6).

## 12. Версия 0.7 (2026-11-18)

План и выбор вариантов — `docs/PLAN-0.7.md`, аудиты — `docs/audits/`.
- **Безопасность.** Другие приложения не могут выключить защиту (переключение только через
  неэкспортируемую активность). Трансляция pcap: по USB — абстрактный сокет только для adb/root, по

  для загрузок и импорта.

  страны/AS без базы GeoIP показаны неактивными.
