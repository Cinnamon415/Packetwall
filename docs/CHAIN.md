# Packetwall в цепочке с прокси-клиентом

Android даёт работать только одному VPN. Поэтому Packetwall и прокси-клиент (v2rayNG, NekoBox,
Hiddify, FlClash, Clash Meta, sing-box) соединяются цепочкой:

```
приложения → Packetwall (VPN: правила, журнал, пакеты) → прокси-клиент (127.0.0.1:порт) → сервер
```

- VPN — у Packetwall.
- Клиент работает в режиме «только прокси»: VPN не поднимает и слушает локальный порт SOCKS5/HTTP.
- Packetwall отправляет туда разрешённый трафик.

Правила, журнал и пакеты работают до прокси, поэтому Packetwall видит настоящие приложения и
адреса.

Подойдёт любой клиент, у которого есть режим «только прокси» и локальный порт SOCKS5 или HTTP. Нельзя
поставить в цепочку клиенты без локального прокси: WireGuard, AmneziaVPN, Outline, OpenVPN. Они
умеют работать только как VPN.

## Общий порядок

1. В клиенте включите режим «только прокси» и запомните порт (ниже — для каждого клиента).
2. Подключитесь в клиенте к серверу, как обычно.
3. В Packetwall откройте **Настройки → Внешний прокси (upstream)** (см. ниже) и нажмите **Проверить**.
4. Включите защиту в Packetwall. Если она уже была включена, выключите и включите снова: настройки
   применяются при следующем включении.

Клиенту стоит отключить оптимизацию батареи (Настройки Android → Приложения → клиент → Батарея → Без
ограничений). Если Android выгрузит клиент, Packetwall покажет «Прокси недоступен», а аварийная
блокировка не выпустит трафик мимо прокси.

## Настройки Packetwall

**Настройки → Внешний прокси (upstream)**:

| Пункт | Значение |
|---|---|
| Пускать трафик через SOCKS5-прокси | включить |
| Охват | **Весь трафик** — всё разрешённое идёт через прокси. **Только правила с маршрутом «через upstream»** — только выбранное правилами |
| Тип | **SOCKS5** (UDP тоже через прокси) или **HTTP CONNECT** (только TCP) |
| Хост | `127.0.0.1` |
| Порт | порт клиента из таблицы ниже |
| Логин / Пароль | только если в клиенте включена аутентификация локального прокси |
| Приложение-прокси (исключается из VPN) | **сам клиент**: его соединения с сервером идут мимо Packetwall, иначе трафик зациклится |
| UDP | **Через прокси (UDP ASSOCIATE)** — для SOCKS5; иначе **Блокировать** (приложения перейдут на TCP) |
| Если прокси недоступен | **Аварийная блокировка (kill switch)** — ничего не уйдёт мимо прокси; **Напрямую** — трафик пойдёт без прокси |

Что Packetwall делает сам:

- **DNS.** При «Весь трафик» DNS идёт через прокси (DNS-over-HTTPS), а не к DNS сети.
- **Ping.** SOCKS5 и HTTP не передают ICMP. Поэтому ping к адресам за прокси отвечается после проверки
  соединения TCP через прокси и напрямую не уходит.
- **Постоянная VPN.** Включайте её для Packetwall, а не для клиента: VPN у Packetwall. Но
  **«Блокировать соединения без VPN» в цепочке не включайте.** В этом режиме Android пускает в сеть
  только VPN-приложение, а приложения, исключённые из VPN, отрезает. Клиент исключён из VPN
  (иначе петля), поэтому перестаёт подключаться к серверу, и не работает ничего. От утечек мимо
  прокси защищает аварийная блокировка Packetwall.

## Порты и пункты меню клиентов

| Клиент | Режим «только прокси» | Порт по умолчанию | Тип в Packetwall |
|---|---|---|---|
| v2rayNG | Настройки → Режим → Прокси | 10808 | SOCKS5 |
| NekoBox | Настройки → Сервисный режим → Только прокси | 2080 | SOCKS5 |
| Hiddify | Настройки → Входящие → Режим службы → Только прокси | 12334 | SOCKS5 |
| FlClash | Инструменты → Расширенная конфигурация → Сеть → VPN: выкл | 7890 | SOCKS5 |
| Clash Meta for Android | Настройки → Сеть → Маршрутизировать системный трафик: выкл | задать в «Переопределении» | SOCKS5 |
| sing-box (SFA) | в конфиге нет `tun`, есть `mixed` | задать в конфиге | SOCKS5 |

Пункты меню сверены с исходниками клиентов (ноябрь 2026): v2rayNG и NekoBox — текущий код, FlClash
0.9.4, Hiddify 5.5.5, Clash Meta for Android 2.11.37, sing-box for Android — текущий код. В других
версиях названия могут немного отличаться.

### v2rayNG

1. ☰ → **Настройки** → раздел «Настройки режима» → **Режим** → **Прокси**.
2. Там же, «Настройки ядра»:
   - **Использовать локальный прокси** — включено;
   - **Динамически менять порт локального прокси** — выключено;
   - **Порт локального прокси** — по умолчанию `10808`;
   - **SOCKS5 UDP** — включить, чтобы UDP шёл через прокси.
3. Если задали **Пользователь / Пароль локального прокси**, введите их в Packetwall.
4. Выберите сервер и нажмите ▶.

Packetwall: SOCKS5, `127.0.0.1:10808`, приложение-прокси — v2rayNG, UDP — через прокси.

### NekoBox

1. **Настройки** → «Настройки приложения» → **Сервисный режим** → **Только прокси**.
2. «Входящие настройки» → **Порт прокси SOCKS5** — по умолчанию `2080`. Это смешанный порт:
   SOCKS5 и HTTP на одном порту.
3. Подключитесь.

Packetwall: SOCKS5, `127.0.0.1:2080`, приложение-прокси — NekoBox, UDP — через прокси.

### Hiddify

1. **Настройки** → **Входящие** → **Режим службы** → **Только прокси**.
2. **Порт прокси (SOCKS5/4, HTTP)** — по умолчанию `12334`.
3. **Требовать пароль** обычно выключено. Если включено: логин `hiddify`, пароль — «Пароль прокси»
   из тех же настроек.
4. Подключитесь.

Packetwall: SOCKS5, `127.0.0.1:12334`, приложение-прокси — Hiddify, UDP — через прокси.

### FlClash

1. **Инструменты** → **Расширенная конфигурация** → **Сеть** → переключатель **VPN** — выключить.
   FlClash перестанет поднимать свой VPN и оставит только локальный прокси.
2. **Инструменты** → **Общие** → **Порт** — смешанный порт, по умолчанию `7890`.
3. **Разрешить LAN** не нужно: Packetwall подключается с этого же устройства.
4. Запустите FlClash (кнопка запуска на главном экране).

Packetwall: SOCKS5, `127.0.0.1:7890`, приложение-прокси — FlClash, UDP — через прокси.

### Clash Meta for Android

1. **Настройки** → **Сеть** → **Маршрутизировать системный трафик** — выключить.
2. **Настройки** → **Переопределение** → **Основные** → **Смешанный порт** — задать, например,
   `7890`. Не во всех профилях есть `mixed-port`, поэтому порт лучше задать явно.
3. Запустите.

Packetwall: SOCKS5, `127.0.0.1:7890`, приложение-прокси — Clash Meta for Android, UDP — через прокси.

### sing-box (SFA)

sing-box for Android поднимает VPN только тогда, когда в конфиге есть входящий `tun`. Без него он
работает как обычный прокси.

1. В профиле удалите входящий `tun` и добавьте `mixed`:

```json
"inbounds": [
  { "type": "mixed", "tag": "mixed-in", "listen": "127.0.0.1", "listen_port": 2080 }
]
```

2. Запустите профиль.

Packetwall: SOCKS5, `127.0.0.1:2080`, приложение-прокси — sing-box, UDP — через прокси.

## Если не работает

- **Клиент не подключается, ничего не работает, хотя без защиты всё было в порядке.**
  - Для Packetwall включено «Блокировать соединения без VPN» (Настройки Android → Сеть → VPN →
    Packetwall ⚙). Выключите его, оставьте только «Постоянная VPN». Packetwall при этом может
    показывать «Прокси доступен»: порт клиента отвечает, но сам клиент до сервера не достаёт.
- **«Прокси недоступен» в Packetwall.**
  - Клиент не запущен или не подключён.
  - Неверный порт.
  - Клиент остался в режиме VPN: тогда Android выключит один из двух VPN.
- **Ничего не открывается, хотя прокси доступен.**
  - Не выбрано «Приложение-прокси». Соединения клиента с сервером идут обратно в Packetwall, и
    получается петля.
- **Сайты открываются, а звонки и игры — нет.**
  - UDP заблокирован. Для SOCKS5 выберите «Через прокси (UDP ASSOCIATE)» и проверьте, что UDP
    включён в клиенте (в v2rayNG — «SOCKS5 UDP»).
- **Проверить цепочку.** Откройте в браузере сайт, который показывает ваш IP: должен быть адрес
  сервера, а не провайдера. В Packetwall откройте соединение из Журнала: в «Обзоре» строка «Маршрут — через upstream».
